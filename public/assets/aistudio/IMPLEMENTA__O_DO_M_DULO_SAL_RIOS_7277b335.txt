# IMPLEMENTAÇÃO DO MÓDULO SALÁRIOS E EVOLUÇÃO DA RENDA
## SAVIO FINANA IA

**OBJETIVO:** Criar um módulo independente, editável e integrado ao sistema financeiro, para cadastrar, acompanhar, calcular e comparar a evolução dos salários e demais fontes de renda ao longo dos meses e anos.

Não tratar salário apenas como uma transação comum. Criar um histórico próprio, com informações estruturadas e possibilidade de edição.

Analisar a arquitetura atual antes de modificar os arquivos. Utilizar React, TypeScript, Vite e os mecanismos de persistência já existentes.

### Gráfico 3: Evolução por instituição

Mostrar quanto cada fonte representa na renda total.

### Gráfico 4: Variação mensal

Calcular o crescimento ou redução em relação ao mês anterior.

Fórmula:

```typescript
export function calculateMonthlyVariation(
  current: number,
  previous: number
): number | null {
  if (previous === 0) return null;

  return ((current - previous) / previous) * 100;
}
```

### Gráfico 5: Comparação anual

Não comparar um ano completo com um ano incompleto sem informar a diferença.

## 7. REAJUSTES SALARIAIS

Criar uma funcionalidade para registrar reajustes.

Cada reajuste deverá possuir:

- Instituição.
- Valor anterior.
- Novo valor.
- Percentual de reajuste.
- Data de vigência.
- Descrição.

Fórmula:

```typescript
export function calculateSalaryAdjustment(
  oldAmount: number,
  newAmount: number
): number | null {
  if (oldAmount <= 0) return null;

  return ((newAmount - oldAmount) / oldAmount) * 100;
}
```

Manter o histórico dos reajustes.

Não alterar automaticamente os registros dos meses anteriores quando houver um novo reajuste.

## 10. INTEGRAÇÃO COM TRANSAÇÕES

Quando um salário for marcado como efetivamente recebido, oferecer a opção de criar uma transação de entrada na conta correspondente.

Criar vínculo entre o registro salarial e a transação gerada.

Impedir que o mesmo salário seja contabilizado duas vezes nos relatórios.

Quando o salário for apenas previsto, não contabilizar como receita efetivamente recebida.

Se a transação for editada ou excluída, manter a consistência do registro salarial.

Transferências entre contas próprias não devem ser classificadas como novos salários.
